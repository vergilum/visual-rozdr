# Уменьшение размера desktop-поставки

## Первый шаг: зависимости frontend

Дата контрольной сборки: 2026-10-16.

В `frontend/package.json` React, React DOM, QRCode, Vite, TypeScript и React Vite plugin перенесены в `devDependencies`. Версионные ограничения сохранены, lockfile обновлён. Frontend по-прежнему собирается Vite, а Electron загружает готовые assets через FastAPI. Main/preload не импортируют эти npm-пакеты: используют Node.js built-ins, Electron и локальные `.cjs`-модули.

## Измерения

Сравнение сделано с существующей `artifacts/portable/win-unpacked/`; контрольная сборка находится в `artifacts/size-audit/win-unpacked/`.

| Метрика | Старая сборка | Контрольная сборка |
| --- | ---: | ---: |
| Вся распакованная папка, приблизительно | 872 МиБ | 813 МиБ |
| `resources/app.asar`, приблизительно | 44 МиБ | 24 КиБ |
| `resources/app.asar.unpacked`, приблизительно | 16 МиБ | отсутствует |
| Логический объём `node_modules` в ASAR, включая unpacked entries | 61 182 636 байт | 0 байт |

Уменьшение распакованного приложения — примерно 59 МиБ (около 7%). Измерения округлены; контрольная сборка также включает последние изменения исходников. Это не измерение размера нового portable EXE: такой EXE в рамках этой проверки не создавался.

FFmpeg runtime, изображения тем и настройки подготовки видео не изменялись. Занимаемый разработческим `frontend/node_modules/` объём ожидаемо почти не сокращается: сборочные инструменты всё ещё нужны разработчику, но теперь не дублируются в desktop-поставке.

## Воспроизведение проверки

1. Из `frontend/`: `npm ci`, затем `npm run desktop:package:audit`.
2. Из корня: `.venv\Scripts\python.exe -m pytest backend/tests`.
3. Из корня: `.venv\Scripts\python.exe scripts\smoke_packaged_backend.py`.
4. В контрольном `resources/app.asar` должны остаться `electron/` и `package.json`, без `node_modules/`.
5. Вручную запустить `artifacts/size-audit/win-unpacked/Visual Pozdr.exe`, проверить окно оператора, открытие экрана, QR, обе темы и воспроизведение видео со звуком.

Smoke-проверка запускает именно PyInstaller EXE из контрольной сборки. Использует отдельную временную папку, пустой токен и свободный порт; проверяет `/api/health`, `/admin`, `/screen`, JS/CSS assets, WebSocket snapshot, bundled FFmpeg/ffprobe и остановку по desktop pipe с кодом 0. Пользовательская база и Telegram polling в проверке не используются.

Автоматические результаты первого шага: 71 backend-тест прошёл, Vite/PyInstaller/Electron directory build выполнены, packaged-backend smoke прошёл. Ручная проверка GUI, реального Telegram и звука в этот замер не входит.

## Последующие кандидаты

- FFmpeg runtime занимает около 435 МиБ. Подбор меньшей сборки требует сравнения поддерживаемых операций и испытаний реальных входных видео, без изменения параметров кодирования и качества.
- PyInstaller backend занимает около 43 МиБ. Сужение `--collect-all` рассматривается после проверки динамических импортов.
- Старые артефакты и `build/` увеличивают рабочую папку проекта, но не расход RAM и не размер новой поставки. Их очистка — отдельная операция.

Уменьшение файлов сборки не означает уменьшения оперативной памяти на ту же величину. RAM требует отдельного замера в ожидании, во время обработки и после серии показов.
