# Архивная проверка этапа 4 на Windows

Этот файл фиксирует историческую проверку серверной очереди до реального экрана. Текущий актуальный чек-лист находится в `docs/STAGE_5_WINDOWS_CHECK.md`.

## Цель

Проверить, что готовые ролики проходят модерацию, попадают в серверную очередь, а команды показа меняют состояние только на сервере и безопасны при повторе.

## Команды

```powershell
.\.venv\Scripts\python.exe -m pytest
cd frontend
npm run build
cd ..
.\.venv\Scripts\python.exe run_server.py
```

Если зависимости ещё не установлены, выполните установку из `README.md`.

## Ручная проверка

1. Откройте `http://127.0.0.1:8000/admin`.
2. Создайте или выберите мероприятие.
3. Откройте приём сообщений.
4. Оставьте режим модерации `manual`.
5. Отправьте настоящий Telegram-видеокружочек через ссылку мероприятия.
6. Дождитесь статуса `ready` в блоке «Принятые кружочки».
7. Убедитесь, что ролик появился в блоке «На проверке», но не появился в очереди.
8. Измените имя гостя и нажмите «Одобрить».
9. Убедитесь, что ролик появился в блоке «Очередь».
10. Добавьте второй ролик и проверьте кнопки «Выше» и «Ниже».
11. Нажмите «Запустить» и убедитесь, что появился текущий ролик с `playback_id`.
12. Нажмите «Пауза», затем «Продолжить»: текущий ролик не должен смениться.
13. На актуальном этапе 5 завершение текущего ролика отправляет только `/screen` по реальному событию окончания видео.
14. Нажмите «Пропустить»: текущий ролик должен уйти из активной очереди без добавления на стену.
15. Нажмите «Остановить показ»: текущий ролик должен вернуться в начало очереди, состояние показа должно стать `stopped`.
16. Перезапустите сервер во время текущего показа и проверьте, что ролик вернулся в очередь, а показ остановлен.

## Ожидаемый результат

- `GET /api/health` возвращает `stage: 4`.
- Ручная модерация не добавляет ролик в очередь до одобрения.
- Автоматическая модерация добавляет готовый ролик в очередь без ручного действия.
- Повторное одобрение не создаёт второй активный `QueueItem`.
- Каждый запуск текущего ролика имеет уникальный `playback_id`.
- Устаревшие playback-события не продвигают очередь; это покрыто автотестами.
- `/screen` пока остаётся экраном ожидания. Реальное воспроизведение относится к этапу 5.
