# Проверка этапа 9 на Windows

## Цель

Проверить, что оператор может запустить проект одним `.bat`-файлом, получить понятные ошибки перед стартом и пройти финальную приёмку перед мероприятием.

## Автоматические проверки

Выполнить из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest
cd frontend
npm run build
cd ..
```

Автотесты покрывают:

- `GET /api/health` возвращает `stage: 9`;
- preflight требует `.env`;
- preflight принимает минимальный локальный `.env`;
- preflight парсит значения `.env`;
- проверки этапов 1-8 остаются рабочими.

## Ручная проверка запуска

1. Убедитесь, что `.env` создан из `.env.example`.
2. Убедитесь, что выполнен `npm run build` в `frontend`.
3. Дважды кликните `start_visual_pozdr.bat`.
4. Дождитесь сообщения `OK: проверки запуска пройдены`.
5. Убедитесь, что открылся `/admin`.
6. Откройте `/api/health` и проверьте `stage: 9`.
7. Откройте `/screen` на втором мониторе или во второй вкладке.

## Ручная проверка ошибок preflight

1. Временно переименуйте `.env` в `.env.backup`.
2. Запустите `start_visual_pozdr.bat`.
3. Должно появиться понятное сообщение о необходимости создать `.env`.
4. Верните `.env` обратно.
5. Временно укажите занятый `PORT` или запустите второй экземпляр.
6. Preflight или lock должны остановить второй запуск с понятным сообщением.

## Финальная приёмка

1. Выполните `docs/EVENT_30_MIN_CHECKLIST.md`.
2. Выполните `docs/FINAL_SMOKE_TEST.md`.
3. Проверьте сценарий восстановления из `docs/RECOVERY_SCENARIOS.md` хотя бы для закрытого `/screen` и перезапуска сервера.

## Ожидаемый результат

- Оператор запускает приложение через `start_visual_pozdr.bat`.
- Ошибки запуска понятны без чтения логов Python.
- `/admin`, `/screen` и Telegram-сценарий проходят финальный smoke-test.
