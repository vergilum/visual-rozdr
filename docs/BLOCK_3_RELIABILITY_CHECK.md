# Блок 3: проверка надёжности

Проверять исходный проект. Пересборка portable EXE для этого блока не требуется.

## Автоматические проверки

Из корня проекта: `.venv\Scripts\python.exe -m pytest backend/tests`.

`backend/tests/test_reliability.py` проверяет изменение состава WebSocket-клиентов во время рассылки, медленного клиента, очистку ошибочной/удалённой обработки, отмену subprocess, согласованный snapshot и запуск/штатную остановку настоящего backend через desktop pipe без Telegram-токена.

## Ручная проверка

1. Запустить исходную desktop-версию: из `frontend/` выполнить `npm run desktop:dev`.
2. Открыть экран из панели и проверить существующее воспроизведение, паузу и остановку.
3. Открыть дополнительную панель в браузере, затем закрыть её во время обновлений. Основная панель и экран продолжают работать.
4. Отправить Telegram-кружочек, дождаться подготовки и убедиться, что доступны видео и JPEG-превью.
5. Удалить другую отправку во время подготовки. После завершения worker не должно остаться файлов этой отправки в `data/temp/` и постоянных папках мероприятия.
6. Закрыть все окна Electron во время подготовки. В диспетчере задач не должно остаться запущенных им backend/FFmpeg; в `logs/backend.log` ожидаются `Application shutdown complete` и завершение с кодом 0.
7. Снова запустить приложение. Данные сохранены; незавершённая обработка возвращается в подготовку, незавершённый показ — в очередь, показ остановлен.

Для browser-режима остаётся штатное завершение сервера через Ctrl+C.
