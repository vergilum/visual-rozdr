# Проверка этапа 8 на Windows

## Цель

Проверить базовую надёжность локального запуска: один экземпляр приложения, восстановление после старта, очистку временных файлов и диагностику свободного места.

## Автоматические проверки

Выполнить из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest
cd frontend
npm run build
cd ..
```

Автотесты покрывают:

- `GET /api/health` возвращает `stage: 8`;
- второй экземпляр storage lock не получает;
- `data/temp` очищается при `init`;
- при низком свободном месте Telegram-приём не создаёт submission;
- существующие проверки приёма, подготовки, модерации, очереди, экрана и стены.

## Ручная проверка двойного запуска

1. Запустите сервер: `.\.venv\Scripts\python.exe run_server.py`.
2. Откройте второй PowerShell в той же папке.
3. Повторите запуск: `.\.venv\Scripts\python.exe run_server.py`.
4. Второй процесс должен завершиться ошибкой `Another Visual Pozdr instance is already running`.
5. Первый процесс должен продолжить работу.

## Ручная проверка восстановления

1. Запустите сервер и подготовьте один ролик до очереди.
2. Запустите показ.
3. Остановите сервер во время текущего ролика.
4. Запустите сервер снова.
5. Текущий ролик должен вернуться в очередь, а состояние показа должно быть `stopped`.
6. В `/admin` проверьте, что история и стена сохранены.

## Ручная проверка временных файлов

1. Остановите сервер.
2. Создайте тестовую папку `data/temp/manual-test` и файл внутри неё.
3. Запустите сервер.
4. Убедитесь, что `data/temp/manual-test` удалена.
5. Убедитесь, что файлы в `data/events/<event_id>/playback` и `thumbnails` не удалены.

## Ручная проверка диска

1. Откройте `/admin`.
2. В блоке «Диагностика» проверьте `disk`, `free_disk_mb` и порог `MIN_FREE_DISK_MB`.
3. При нормальном свободном месте статус должен быть `ok`.
4. Для проверки низкого порога можно временно поднять `MIN_FREE_DISK_MB` в `.env` выше свободного места и перезапустить сервер.
5. После этого новые Telegram-кружочки должны получать сообщение о недостатке места и не создавать запись в базе.
6. Верните нормальный `MIN_FREE_DISK_MB`, например `1024`.

## Ожидаемый результат

- Работает только один экземпляр приложения.
- После перезапуска незавершённый показ не теряется и не считается завершённым.
- Временные неполные файлы очищаются при старте.
- Недостаток места не расходует лимит гостя и виден оператору.
