# Архивная проверка этапа 1 на Windows

Этот файл фиксирует историческую проверку каркаса. Текущий актуальный чек-лист находится в `docs/STAGE_4_WINDOWS_CHECK.md`.

## Цель

Проверить, что локальный сервер запускается, SQLite сохраняет состояние, а простые страницы `/admin` и `/screen` получают snapshot с сервера.

## Команды

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
cd frontend
npm install
npm run build
cd ..
py run_server.py
```

Если порт `8000` занят другим процессом, укажите другой порт в `.env`, например `PORT=8010`, и открывайте адреса с этим портом.

## Ручная проверка

1. Откройте `http://127.0.0.1:8000/admin`.
2. Создайте мероприятие.
3. Откройте `http://127.0.0.1:8000/screen`.
4. Проверьте, что на экране отображаются название компании и текст мероприятия.
5. Вернитесь в `/admin`, измените текст экрана и статус приёма.
6. Обновите `/screen` и проверьте изменения.
7. Перезапустите сервер и убедитесь, что данные остались.

## Ожидаемый результат

- В папке `data/` создана база `app.sqlite3`.
- В `/admin` видна активная карточка мероприятия.
- В `/screen` виден экран ожидания.
- В текущей версии `GET /api/health` возвращает актуальный номер этапа.
- Telegram, обработка видео, модерация и очередь уже добавлены после этапа 1.
