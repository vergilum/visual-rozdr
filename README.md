# Visual Pozdr

Локальная система видеопоздравлений для мероприятий.

Версия приложения: **0.1.1 (011)**. Файлы поставки и инструкция обновления:
[docs/RELEASE_011.md](docs/RELEASE_011.md).

Текущий статус: реализован этап 12.1 — локальная система с приёмом Telegram-видеокружочков, подготовкой через FFmpeg, модерацией, серверной очередью, Electron-окнами оператора и экрана, а также portable Windows EXE без обязательных Python, Node.js, PowerShell или установленного FFmpeg.

## Что есть сейчас

Для macOS подготовлены платформенный запуск и workflow демо-сборки arm64/x64. ZIP с
`Visual Pozdr.app` собирается на macOS, содержит backend, FFmpeg/ffprobe и обе темы.
Получатель указывает своего бота в личном `.env`; GitHub ему не нужен.
Сборка: [docs/MAC_DEMO_BUILD.md](docs/MAC_DEMO_BUILD.md).
Запуск и ручная проверка: [docs/MAC_DEMO_USER_GUIDE.md](docs/MAC_DEMO_USER_GUIDE.md).
Готовность конкретного Mac-архива определяется результатом workflow и отчётом ручной проверки.
Первые arm64/x64 ZIP успешно собраны и автоматически проверены на macOS 15.7.9:
[отчёт, пути и контрольные суммы](docs/MAC_DEMO_VERIFICATION.md).
Golden Gate 27.0.1, настоящий Telegram, звук и проектор ещё требуют проверки получателем.

- FastAPI backend на `127.0.0.1:8000`.
- SQLite база `data/app.sqlite3`.
- Начальная схема данных из ТЗ: мероприятия, привязки гостей, submissions, queue items, playback sessions, audit entries.
- API состояния: `GET /api/state`.
- Health endpoint: `GET /api/health`.
- Создание, выбор и обновление мероприятия.
- WebSocket `/api/ws` со snapshot состояния.
- React-интерфейс `/admin` и экран трансляции `/screen`.
- Сохранение мероприятия и настроек после перезапуска.
- aiogram long polling как фоновая задача приложения.
- `/start <код>` для привязки гостя к мероприятию.
- `/start` без кода и `/help` с инструкциями.
- Приём только Telegram `video_note` для активного мероприятия с открытым приёмом.
- После каждого полученного кружочка бот спрашивает стол для этого видео. До 15 столов выводятся страницами по 5 кнопок.
- До выбора стола ролик хранится только как временное ожидание на 15 минут, не обрабатывается и не расходует лимит. Один аккаунт может выбирать разные столы для разных роликов.
- Сохранение входящего `video_note` в SQLite со статусом `received` перед фоновой подготовкой.
- Защита от дублей по `telegram_chat_id + telegram_message_id`.
- Фоновая подготовка видео без блокировки API и Telegram-бота.
- Переходы подготовки `received` → `downloading` → `processing` → `ready` или `failed`.
- Скачивание оригинала из Telegram во временную папку.
- Проверка файла через `ffprobe` по фактическому размеру, длительности и наличию видеодорожки.
- Подготовка браузерного MP4 через FFmpeg: H.264, `yuv420p`, AAC при наличии звука, `faststart`.
- Создание JPEG-превью.
- Сохранение готовых файлов в `data/events/<event_id>/originals`, `playback`, `thumbnails`.
- Кнопка повторной обработки для технически ошибочных роликов.
- Ручная модерация готовых роликов: предпросмотр, изменение имени гостя, одобрение и отклонение.
- Автоматическая модерация: готовый ролик одобряется, но не попадает в очередь или на стену без действия оператора.
- Команда «Одобрить все ожидающие» с подтверждением.
- Серверная очередь как видимый плейлист с изменением порядка, удалением ожидающих элементов и повторным показом через новый `QueueItem`.
- Кнопка «Показать повторно» для уже одобренных роликов создаёт новый элемент очереди.
- Управление состоянием показа: `start`, `pause`, `resume`, `skip`, `stop`.
- Для каждого запуска создаётся уникальный `playback_id`; устаревшие события завершения/ошибки не продвигают очередь.
- После перезапуска незавершённый `playing` ролик возвращается в очередь, а показ останавливается.
- `/screen` регистрируется как единственный активный экран и отправляет heartbeat.
- Вторая вкладка `/screen` получает режим `secondary` и не запускает звук.
- Экран воспроизводит только текущий ролик, выбранный сервером, и отправляет `started`, `completed`, `error` с текущим `playback_id`.
- После команды «Запустить» показ продолжает по кругу элементы операторской стены до команды «Остановить показ» в `/admin`.
- После завершения сервер сохраняет историю показа и создаёт следующий технический `QueueItem` из стены.
- Циклический показ не зависит от количества роликов на стене.
- Режим показа переключается между «Автопоказом» и «Интерактивной стеной».
- В режиме «Интерактивная стена» `/screen` показывает элементы `state.wall`, а ролик запускается только кликом по конкретному шарику/кружочку.
- В `/admin` оператор может запустить конкретный ролик стены кнопкой «Запустить», если активный экран свободен. Команда создаёт новый `QueueItem`, не прерывает текущий ролик и блокируется с подсказкой, пока показ уже идёт.
- После естественного завершения ролик из интерактивной стены остаётся открытым: его можно повторить. Крестик подтверждает завершение серверу и возвращает стену; следующий ролик не выбирается автоматически.
- Новые ролики попадают в автопоказ только после ручного добавления на стену.
- Пауза/продолжение с панели управляют видеоэлементом без сброса позиции.
- При потере heartbeat активного экрана сервер возвращает текущий ролик в очередь и останавливает показ.
- В browser-режиме `/screen` сразу пробует запуск по команде панели. Только при фактической блокировке звука браузером появляется просьба нажать существующую кнопку «Запустить показ» на экране. Предварительная подготовка не требуется; Electron использует тот же server-driven сценарий.
- QR-код подключения строится по Telegram-ссылке мероприятия.
- Карточка приглашения на `/screen` увеличена в обеих темах: ширина до 1080 px, QR-код около 400×400 px на Full HD и 280×280 px при 1366×768. Текст поздравления и инструкция компактнее, чтобы основное место занимал QR-код. Размеры адаптируются к окну; на маленьком экране карточку можно прокрутить. QR генерируется в разрешении 640 px с белым полем для сканирования.
- В карточке приглашения название мероприятия выводится под компанией (если заполнено), а поздравление из поля «Текст экрана» — справа от QR-кода, над приглашением и инструкцией. На узком окне текст переносится под QR-код. Текстовая Telegram-ссылка на гостевом экране не отображается; в панели оператора она остаётся доступна.
- `/admin` разделён на блоки: мероприятие, текущий показ, проверка, очередь, история, ошибки подготовки, настройки и диагностика.
- В `/admin` оператор настраивает число столов от 1 до 15 и необязательные задания, видит постоянную метку стола на роликах и фильтрует модерацию и принятые кружочки по столу.
- Во время показа под именем гостя выводятся стол и его задание; если задание пустое, выводится только номер стола.
- История показывает завершённые, пропущенные и ошибочные показы; кнопку «Очистить историю» можно использовать без удаления роликов, очереди, стены и файлов.
- Стена на `/screen` показывает до 12 выбранных оператором поздравлений; добавление тринадцатого отклоняет сервер.
- Повторный показ и завершение ролика не создают второй элемент на стене.
- В `/admin` есть блок «Стена» с кнопками запуска ролика и удаления поздравления только со стены.
- Блок «Принятые кружочки» показывает только ролики активного мероприятия.
- Кнопка «Удалить полностью» доступна в принятых кружочках, очереди, истории и ошибках подготовки. После подтверждения ролик удаляется из базы, очереди, истории, стены и файлов. Удаление запрещено только если ролик сейчас воспроизводится.
- Ошибки подготовки вынесены отдельно с кнопкой повторной обработки.
- Прогресс текущего ролика поступает от активного `/screen` через heartbeat.
- Настройки компании, текста, громкости, ограничений, цветов и фонового изображения сохраняются на сервере.
- Переключение мероприятия во время показа блокируется до остановки показа.
- Второй экземпляр приложения не запускается одновременно с первым благодаря lock-файлу `data/app.lock`.
- При старте очищается `data/temp`, а незавершённые обработки возвращаются в очередь подготовки.
- Диагностика показывает свободное место на диске и порог `MIN_FREE_DISK_MB`.
- При недостатке свободного места новые Telegram-кружочки технически не принимаются и не расходуют лимит гостя.
- Desktop-оболочка Electron запускает локальный backend и открывает окно оператора; экран трансляции открывается вручную из панели.
- Portable `VisualPozdr.exe` включает frontend, PyInstaller backend, FFmpeg и ffprobe; startup-лог backend сохраняется в пользовательской папке Windows.
- Резервный запуск для разработки и диагностики: `start_visual_pozdr.bat`.
- Перед стартом выполняется preflight-проверка `.env`, frontend-сборки, порта, свободного места и внешних инструментов.
- `/screen` использует готовую тему `new_year` из PNG-ассетов в `frontend/public/themes/new_year/`.
- В теме `new_year` шарики привязаны к области ёлки и не меняют координатную систему между ожиданием и показом.
- В теме `neutral` `zone-overlay.png` задаёт белую полупрозрачную рабочую зону шириной 35% фона, где 12 кружочков расположены сеткой 3×4.

## Требования Для Исходников

- Windows 10/11.
- Python 3.12+; в текущей среде используется команда `py`.
- Node.js 24+ и npm 11+.
- Для portable EXE Python, Node.js и FFmpeg не нужны. Они требуются только для запуска и сборки исходников. Для запуска только backend вне проекта нужны `runtime/ffmpeg/` или системный `PATH`.

## FFmpeg Для Разработки Без Electron

Windows-инсталлятор Visual Pozdr содержит `ffmpeg.exe` и `ffprobe.exe`; отдельно устанавливать их на ноутбук мероприятия не нужно. Этот раздел нужен только если backend запускается отдельно от desktop-оболочки и папка `runtime/ffmpeg/` недоступна.

Вариант через winget:

```powershell
winget install Gyan.FFmpeg
```

После установки закройте и заново откройте PowerShell.

Проверьте доступность:

```powershell
ffmpeg -version
ffprobe -version
```

Если команды не найдены, добавьте папку `bin` установленного FFmpeg в переменную среды `PATH` и снова откройте PowerShell.

## Установка на Windows

Откройте PowerShell в папке проекта.

Создайте виртуальное окружение:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите backend-зависимости:

```powershell
py -m pip install -r requirements.txt
```

Установите frontend-зависимости:

```powershell
cd frontend
npm install
cd ..
```

Создайте локальный конфиг при необходимости:

```powershell
copy .env.example .env
```

Без `TELEGRAM_BOT_TOKEN` сервер, `/admin` и `/screen` продолжают работать. Бот в этом случае не запускается.

## Создание Telegram-бота

1. Откройте Telegram и найдите `@BotFather`.
2. Отправьте команду `/newbot`.
3. Укажите имя и username бота. Username должен заканчиваться на `bot`, например `my_event_video_bot`.
4. BotFather выдаст токен. Не публикуйте его и не отправляйте в чат.
5. Впишите токен только в локальный `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_новый_токен
TELEGRAM_BOT_USERNAME=username_бота_без_@
```

Если токен был случайно опубликован, отзовите его через BotFather и создайте новый.

## Desktop-запуск

Для разработки desktop-оболочки из `frontend/`:

```powershell
npm install
npm run desktop:dev
```

Команда запускает Vite, Electron и существующий Python backend. Electron открывает окно оператора. В блоке «Экран показа» выберите монитор, затем откройте, перенесите или закройте отдельное бескаркасное полноэкранное окно трансляции. Повторное открытие переводит в фокус уже открытый экран. Если выбранный монитор отключён, экран автоматически переносится на основной монитор с предупреждением в панели. Backend по-прежнему слушает только `127.0.0.1`.

Если `/admin` открыт в Chrome, Edge или через `start_visual_pozdr.bat`, это browser-режим: список мониторов Windows не появится, а «Открыть в браузере» откроет прежнюю страницу `/screen`. Для управления мониторами запускайте `npm run desktop:dev` либо установленное приложение Visual Pozdr.

Для NSIS-инсталлятора должны быть доступны `.venv` и зависимости из `requirements.txt`. FFmpeg/ffprobe берутся из `runtime/ffmpeg/` и добавляются в установщик автоматически. Из `frontend/` выполните:

```powershell
npm run desktop:package
```

Установщик создаётся в `artifacts/electron/`. При первом запуске packaged-версии шаблон `.env` создаётся в пользовательской папке приложения; заполните там Telegram-настройки. SQLite и медиа также хранятся в этой папке, а не внутри установленного приложения.

На чистом Windows-компьютере после установки откройте `/admin`, проверьте в блоке «Диагностика» статусы `ffmpeg: available` и `ffprobe: available`, версии и пути из `resources/runtime/ffmpeg/`. Затем отправьте тестовый Telegram-кружочек: после `ffprobe`, транскодирования и создания JPEG-превью он должен получить статус `ready`.

## Portable EXE

Для одного запускаемого файла из `frontend/` выполните:

```powershell
npm run desktop:package:portable
```

Результат версии 0.1.1: `artifacts/releases/011/windows/VisualPozdr-011.exe`. Перенесите только этот EXE на ноутбук мероприятия и откройте двойным кликом. Он запускает backend, ожидает его готовность и открывает только окно оператора. Экран трансляции оператор открывает из блока «Экран показа» панели.

При первом запуске приложение создаёт `%APPDATA%/Visual Pozdr/.env`, `%APPDATA%/Visual Pozdr/data/` и `%APPDATA%/Visual Pozdr/logs/backend.log`. Если более ранняя версия уже создала `%APPDATA%/visual-pozdr-frontend/`, её `.env`, SQLite, медиа и логи автоматически переносятся в новую папку. В Electron-панели используйте кнопку «Открыть конфигурацию»: она откроет папку с `.env`. Укажите в нём Telegram-токен и username, сохраните файл и перезапустите приложение. SQLite, очередь, история и медиа остаются в `data/` после перезапуска EXE. Если порт `8000` занят другой программой, portable-версия автоматически выберет свободный порт от `8001` до `8020`; если на порту уже работает Visual Pozdr, второй экземпляр не запускается.

Если EXE показывает ошибку старта, проверьте `%APPDATA%/Visual Pozdr/logs/backend.log`. Сообщение о недостающем frontend, backend, FFmpeg или ffprobe означает повреждённую или неполную сборку.

## Контрольная сборка и размер приложения

Из `frontend/` выполните:

```powershell
npm ci
npm run desktop:package:audit
```

Результат: `artifacts/size-audit/win-unpacked/`. Это полная папка приложения для проверки, а не один переносимый EXE; существующие сборки в `artifacts/electron/` и `artifacts/portable/` не заменяются.

Все npm-зависимости нужны при разработке/сборке и устанавливаются без `--omit=dev`. В готовом desktop-приложении React и QRCode уже включены в `frontend/dist`, а Vite, TypeScript, Babel и другие build-инструменты отдельно не нужны.

Из корня проекта проверьте упакованный backend:

```powershell
.venv\Scripts\python.exe scripts\smoke_packaged_backend.py
```

Проверка использует временную базу и пустой Telegram-токен. Она проверяет HTTP, frontend assets, WebSocket, bundled FFmpeg/ffprobe и штатную остановку. Воспроизведение со звуком и окна Electron проверяются вручную. Замеры размера: `docs/SIZE_AUDIT.md`.

## Резервный запуск на мероприятии

Запускайте приложение двойным кликом по файлу:

```text
start_visual_pozdr.bat
```

Файл проверит `.env`, `.venv`, frontend-сборку, свободное место и порт. После успешной проверки он запустит сервер и откроет `/admin` в браузере.

Окно `start_visual_pozdr.bat` должно оставаться открытым до конца мероприятия. Для остановки нажмите `Ctrl+C` в этом окне.

## Запуск для разработки

Соберите frontend:

```powershell
cd frontend
npm run build
cd ..
```

Запустите локальный сервер:

```powershell
py run_server.py
```

Если PowerShell блокирует активацию `.venv`, можно запускать без активации:

```powershell
.\.venv\Scripts\python.exe run_server.py
```

Если порт `8000` занят, поменяйте `PORT` в `.env`, например:

```powershell
PORT=8010
```

После этого адреса будут начинаться с выбранного порта, например `http://127.0.0.1:8010/admin`.

Откройте:

- `http://127.0.0.1:8000/admin` — панель оператора;
- `http://127.0.0.1:8000/screen` — экран трансляции;
- `http://127.0.0.1:8000/api/health` — проверка API.

## Проверка результата этапа 9

1. Откройте `/admin`.
2. Создайте мероприятие с названием компании.
3. Убедитесь, что оно стало активным и появился код подключения.
4. Измените текст экрана, откройте или закройте приём.
5. Откройте `/screen` во второй вкладке и проверьте, что отображается компания и текст.
6. Убедитесь, что в `/admin` появилась Telegram-ссылка подключения, если задан `TELEGRAM_BOT_USERNAME`.
7. Откройте приём сообщений.
8. Перейдите по Telegram-ссылке подключения и отправьте `/start <код>` через кнопку Start.
9. Отправьте настоящий Telegram-видеокружочек: запишите кружочек камерой внутри чата Telegram, не прикрепляйте обычное видео из галереи. После ответа бота выберите стол для этого ролика.
10. Бот должен ответить: «Кружочек получен, готовим его к показу.»
11. В `/admin` в блоке «Принятые кружочки» запись должна пройти статусы `received`, `downloading`, `processing`, `ready`.
12. Для `ready` должна появиться JPEG-превью и ссылка «Открыть видео».
13. Файлы должны появиться в `data/events/<event_id>/originals`, `playback`, `thumbnails`.
14. В ручном режиме ролик должен появиться в блоке «На проверке» и не должен попасть в очередь или на стену до действия оператора.
15. Нажмите «Одобрить», затем «Добавить на стену»: ролик должен появиться в блоке «Стена».
16. Откройте `/screen` на втором мониторе или во второй вкладке.
17. Предварительный клик на `/screen` не требуется. Если браузер фактически отклонит запуск со звуком на следующем шаге, нажмите «Запустить показ» на `/screen` для повторной попытки.
18. В `/admin` нажмите «Запустить»: первый элемент стены должен стать текущим, а `/screen` должен воспроизвести его в круге со звуком.
19. Нажмите «Пауза» и «Продолжить»: видео должно остановиться и продолжиться с текущей позиции.
20. Дождитесь реального окончания ролика: экран должен отправить `completed`, сервер должен перейти к следующему элементу стены в автопоказе.
20.1. Проверьте два или три ролика подряд без обновления `/screen`: следующий ролик должен запускаться автоматически.
20.2. После завершения ролика состав стены не должен измениться сам собой.
21. Нажмите «Пропустить» на текущем ролике: старое видео должно остановиться, сервер должен выбрать следующий элемент.
21.1. Пропуск не должен менять состав стены.
22. Нажмите «Остановить показ»: текущий ролик должен вернуться в начало очереди, состояние показа должно стать `stopped`, видео на `/screen` должно остановиться.
23. Для завершённого ролика нажмите «Показать повторно» в блоке «Принятые кружочки»: в очереди должен появиться новый элемент.
23.1. Повторный показ этого же ролика не должен создать второй дубль на стене.
23.2. Если элементы стены закончились, показ должен продолжиться по кругу до нажатия «Остановить показ». Проверьте это на любом шаблоне стены.
23.3. В настройках переключите режим показа на «Интерактивная стена»: `/screen` должен показать элементы стены как шарики на ёлке, а клик по шарику должен запустить выбранный ролик.
23.4. После завершения выбранного ролика экран должен остаться открытым. Нажмите «Повторить видео» и убедитесь, что ролик запускается с начала без нового элемента очереди. Нажмите крестик: экран должен вернуться к ёлке, а шарик остаться доступным для повторного клика.
24. Откройте вторую вкладку `/screen`: она должна показать сообщение, что экран уже занят, и не должна запускать звук.
25. Закройте активный `/screen` во время показа или дождитесь потери heartbeat: текущий ролик должен вернуться в очередь, а показ остановиться.
26. Закройте приём и отправьте ещё один кружочек: бот должен сообщить, что приём завершён.
27. Проверьте `/admin`: история должна показывать завершённые/пропущенные/ошибочные показы, а ошибки подготовки должны быть в отдельном блоке.
27.1. Нажмите «Очистить историю»: история должна стать пустой, а очередь, стена и файлы должны остаться на месте.
28. Измените настройки цвета, громкости и текста: `/screen` должен применить их без перезапуска.
29. Для фонового изображения используйте 1920x1080 или 2560x1440; важные детали держите по центру, потому что края могут обрезаться.
30. Проверьте блок «Диагностика»: `disk` должен быть `ok`, а `free_disk_mb` должен быть выше `MIN_FREE_DISK_MB`.
31. Попробуйте запустить второй сервер параллельно первому: второй запуск должен завершиться ошибкой двойного экземпляра.
32. Запустите приложение через `start_visual_pozdr.bat` и убедитесь, что `/admin` открылся автоматически.

Если `ffmpeg` или `ffprobe` отсутствуют, сервер и бот продолжают работать, а в диагностике панели будет показана причина недоступности обработки.

## Границы этапа 9

В этом этапе намеренно не реализованы:

- полноценное оформление экрана.
- одноразовый экспорт архива;
- автоматическая ротация логов;
- длительный двухчасовой прогон на реальном проекторе.
